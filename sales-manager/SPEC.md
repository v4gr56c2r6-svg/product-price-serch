# 絶叫焼き Sales Manager — 初版仕様

## 目的

絶叫焼きの営業日報をPC・スマートフォンで入力し、売上を日別・月別に振り返る。初版は既存Numbersの日報項目と商品・価格の記録をWeb入力へ置き換える。

## 画面

1. **ダッシュボード**：選択月の売上、客数、客単価、日報件数、日別売上グラフ、最近の日報。
2. **日報入力**：営業日、売上、客数、商品別販売数、天気、最高気温、混雑、品切れ商品、廃棄、特記事項。
3. **日別・月別集計**：月間合計と平均、日別売上グラフ、日報一覧、商品別販売数・参考金額。
4. **商品・価格一覧**：商品名・価格の手入力、編集、削除、JSONバックアップの保存と読み込み。

## 計算ルール

- 客単価 = 売上 ÷ 客数。客数が0の場合は0円。
- 月間売上・客数は日報値を合算。平均客単価 = 月間売上 ÷ 月間客数。
- アイス・箱入りの数量は、該当する商品別販売数を合算する。
- 商品別参考金額 = 日報入力時に保存した商品価格 × 販売数。レジ売上とは独立した参考値。
- 同じ営業日の保存は既存日報の更新として扱う。

## データの扱い

- 日報は営業日をキーとしてブラウザのローカル保存領域へ保存する。
- 商品マスターは初期状態で空にし、利用者が画面から手入力する。商品名・価格は暗号化してブラウザ内へ保存し、公開ソースには含めない。
- 入力時点の商品名・価格を日報にも保存し、将来の価格変更で過去の参考金額が変わらないようにする。
- 月次CSVは売上・客数・天候等と全商品の販売数を含める。
- AES-GCMで保管データを暗号化し、鍵はPBKDF2-HMAC-SHA256（600,000回）で12文字以上のパスワードから導出する。パスワードは保存・送信しない。
- JSONバックアップも暗号化し、読み込みには作成時のパスワードを求める。同じ営業日の重複データは読み込んだ内容で更新する。
- 外部API、クラウドDB、解析タグ、外部フォントは使わず、日報データを外部送信しない。

## 公開・共有時の注意

商品名・価格を公開ソースから分離し、画面で手入力して暗号化保存する。解除中はデータがブラウザメモリ上で読めるため、信頼できる端末で使い、離席時はロックする。パスワードを忘れると復元できない。CSVは平文で出力されるので会社承認済みの保管先を使う。売上日報の複数端末共有はこの初版では行わない。共有が必要になったら、会社が承認した認証・保存基盤とアクセス権限を別途設計する。
